# AI-Ассистент для 1С ERP

Прототип извлекает реквизиты заявки через GigaChat, проверяет их по локальным SQLite-справочникам и после явного подтверждения сохраняет демо-документ «Поступление товаров и услуг».

> Реальная база 1С ERP не подключена. Номера вида `ДЕМО-00000001` относятся только к локальному демо-адаптеру.

## Безопасная настройка

1. Скопируйте `.env.example` в `.env`.
2. Укажите новый Authorization Key в `GIGACHAT_CREDENTIALS`. `.env` исключён из Git, ключ нельзя помещать во frontend, README или `.env.example`.
3. Для проекта физического лица оставьте `GIGACHAT_SCOPE=GIGACHAT_API_PERS`.
4. При необходимости поменяйте `GIGACHAT_MODEL` на модель, доступную вашему проекту.

По умолчанию OAuth-токен запрашивается через `https://ngw.devices.sberbank.ru:9443`, а генерация — через `https://api.giga.chat`. Это разные адреса и они настраиваются отдельно параметрами `GIGACHAT_OAUTH_URL` и `GIGACHAT_BASE_URL`.

Если ключ передавался через чат, письмо или другой открытый канал, отзовите его в кабинете GigaChat и выпустите новый.

## Запуск и проверка

```bash
npm install
npm test
npm run dev
```

Frontend запускается через Vite, API — на `http://localhost:3001`. Учётная запись администратора берётся из `ADMIN_EMAIL` и `ADMIN_PASSWORD`.
Сервер запускает Node с поддержкой системных переменных `HTTP_PROXY`/`HTTPS_PROXY` и системного хранилища доверенных сертификатов, что важно в корпоративной сети. Проверка TLS при этом не отключается.

## Сценарий

1. Пользователь вставляет текст заявки.
2. Сервер получает временный access token GigaChat и запрашивает строго структурированный JSON.
3. Черновик независимо проверяется: тип документа, ИНН/КПП, дата, валюта, строки, арифметика, итог и соответствие локальным справочникам.
4. Ошибочный черновик блокируется и возвращается на уточнение.
5. Проверенный черновик создаётся только после нажатия кнопки подтверждения. Повторный запрос с тем же идентификатором возвращает ранее созданный документ.

## API

- `POST /api/documents/preview` — извлечение и проверка реквизитов.
- `POST /api/documents/create` — повторная проверка и идемпотентное создание демо-документа.
- `GET /api/directories/counterparties` — локальный справочник контрагентов.
- `GET /api/directories/items` — локальный справочник номенклатуры.
- `GET/POST/PATCH/DELETE /api/journal` — журнал обработки.

Для настоящей интеграции замените реализацию `server/oneCAdapter.ts` на HTTP/OData/расширение 1С, сохранив контракт предпросмотра и создания.
